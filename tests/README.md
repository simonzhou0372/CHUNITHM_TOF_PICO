# Firmware fault-injection tests

Run from the repository root. Build the firmware first so that the USB test
can read the actual patched TinyUSB source generated by CMake.

```powershell
& 'C:/Users/alskqqq/.pico-sdk/cmake/v4.3.4/bin/cmake.exe' --build build --parallel 4
$env:Path = 'C:/msys64/ucrt64/bin;' + $env:Path
& C:/msys64/ucrt64/bin/g++.exe -std=c++20 -O2 -Itests/async_fakes -Isrc tests/async_sensor_test.cpp src/vl53l0x.cpp src/mpr121.cpp -o build/async_sensor_test.exe
& ./build/async_sensor_test.exe
python tests/usb_ep0_test.py --compiler C:/msys64/ucrt64/bin/g++.exe
```

`async_sensor_test.cpp` runs the production I2C engine, MPR driver, ToF driver
and Core1 scheduler against deterministic register and clock models. It covers:

- TX FIFO full, missing RX/STOP, disable/reset completion stuck, deadline expiry,
  exact RESTART/STOP placement, stale FIFO cleanup and I2C instance isolation.
- Five-sensor startup, SPAD/calibration timeout, actual timing-budget programming
  and readback through the production formulas.
- One sensor absent, the shared bus stuck, two sensors spontaneously reset and
  all five spontaneously reset. No address/configuration write may target
  multiple sensors at their shared default address. All five must recover
  unique addresses and snapshots younger than 50 ms.
- Core1 keeps advancing while MPR runs interleaved, no coroutine frame exhaustion
  or accumulated frame leak, unchanged MPR configuration/filters/touch bits.
- Overlapping CONFIG commands converge on the newest values; RESET reapplies
  the saved configuration.

`usb_ep0_test.py` extracts the **actual generated** EP0 reset and deferred-task
functions, compiles them with register stubs, and checks immediate return without
ABORT completion, successful one-time SETUP delivery, the 1 ms deadline across
clock wrap, IRQ disable on timeout, and the original B0/B1 path.

The older `i2c_bounded_test.cpp` and `fakes/` exercise the previous synchronous
helper. That helper is no longer used by the firmware; those tests alone do not
validate the current transport.

These tests validate control flow and register sequencing. They do not simulate
electrical timing, interrupt arbitration, flash hardware, real USB enumeration,
or the complete ST sensor state machine. Physical soak testing remains necessary.
See [the current audit](../docs/USB_DROPOUT_2026_09_20.md).
